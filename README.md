Noa's Ark Hotel Management System
A full-stack starter application for a Kenyan hotel/restaurant. It includes a customer-facing QR menu, table-specific QR codes, front desk order intake, kitchen workflow, cashier checkout, payment records, printable receipts, stock tracking, low-stock alerts, and payment reports.
Stack
Frontend: HTML5, CSS, vanilla JavaScript
Backend: Node.js + Express REST API
Database: SQLite (data/noas-ark.sqlite, persistent local file)
QR codes: Generated by the backend using qrcode
Requirements
Install Node.js 18+ and npm.
Run locally
npm install
npm start
Open http://localhost:3000. The SQLite database, 12 tables, sample Kenyan menu and sample inventory are initialized automatically on first run.

Order flow
Guest QR order → Front desk accepts (Accepted) → Send to kitchen (Preparing) → Mark ready (Ready) → Serve (Served) → Cashier records payment → receipt.
Features
12 seeded tables (T01–T12) with individual QR codes
Kenyan menu examples: nyama choma, ugali/sukuma/beef, githeri, mukimo, pilau, matoke, fish tilapia, chapati, mandazi, chai, fresh juice and more
Orders with status workflow and item notes
Cashier supports cash, M-Pesa, card and bank transfer recording, partial payments, references and printable receipts
Store inventory with opening quantities, reorder thresholds, cost values, adjustments, and low-stock alerts
Daily dashboard and payment-method sales reports
SQLite data persists across server restarts
Important production notes
This is a functional local starter, not yet a hardened production deployment. Before live hotel use, add staff authentication and role permissions, HTTPS, backups, audit logging, CSRF/rate-limit protections, and a hosted database/monitoring strategy. Payment entries are records only: no money is moved by this app. Live M-Pesa requires a Safaricom Daraja integration and secure server-side callback verification; card payments require a compliant payment provider. Inventory quantities are currently adjusted manually; connect menu recipes/BOMs to decrement ingredient stock automatically after confirmed kitchen preparation if you need ingredient-level consumption accounting.
